# Juju 桌面重写开发计划

**状态：** 实施计划  
**适用工程：** `desktop/`  
**产品范围：** Windows 桌面应用；Tauri 2 + React + TypeScript + Vite + Rust  
**相关文档：** [`../rewrite-functional-specification.md`](../rewrite-functional-specification.md)、[`../new-ui.md`](../new-ui.md)

本文规定重写的实施顺序和阶段验收。`rewrite-functional-specification.md` 是各工具当前行为和数据格式的基线；如计划与功能规格有差异，以功能规格为准，除非用户另行确认产品行为变更。

## 1. 交付原则

### 1.1 每一步都是可运行产品

阶段是可独立交付的增量版本，不是不能启动的内部施工步骤。每个阶段必须满足：

1. 阶段开始时已有的应用仍能启动；阶段结束时交付可启动、可操作、可验证的应用。
2. 新增能力通过真实界面和真实数据路径验证；未完成的后续能力显示清楚的占位状态，不得留下损坏入口或不可运行的半成品。
3. 提交阶段结果前，实际执行适用的类型检查、lint、格式检查、测试、构建和 Windows Tauri 启动验证；如环境不支持某项验证，明确记录未执行及原因，不得宣称通过。
4. 为每阶段提供用户可重复的运行命令、演示路径、自动化检查和手动验收步骤。
5. 阶段验收通过后再开始下一阶段。每一步都保留前序功能，避免必须等到整个工具完成才能运行产品。

### 1.2 产品与数据约束

- 新工程位于 `desktop/`，旧 .NET/WPF 工程和 `editor/` 保持原位；本计划不要求搬移或删除旧工程。
- Juju 主进程负责托盘、应用级服务和通用任务调度。工具窗口关闭时销毁对应 WebView；关闭最后一个工具窗口不能退出主进程。显式选择托盘“退出”才进入关停流程。
- Toto 提醒不依赖 Toto 窗口存活；调度器不依赖 React 页面或前端计时器。工具向宿主调度器登记任务，工具自身负责业务判断和执行。
- 用户数据采用可直接阅读、编辑的明文文件，不使用 DPAPI 加密。保存需支持原子替换；JSON 文档需检测外部修改和未保存编辑冲突。数据根目录、文件路径和既有格式以功能规格为准。
- 现行 JSON、Toto CSV/配置、MySQL Schema 连接及快照格式和用户可见行为作为迁移基线。MySQL 密码按用户决定以明文保存在连接配置文件中，不写入日志或快照。
- 每个阶段验收后都执行 Windows Release 构建，并交付单文件 `desktop/artifacts/Juju.exe`。只生成可执行文件，不生成 MSI/NSIS 安装文件。
- 本计划不包含自动发布、更新检查、更新下载或自动升级。Release EXE 是每个阶段的本地可运行交付物。

### 1.3 每阶段共同验收门槛

阶段具体验收条件之外，每阶段都须满足：

```text
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
pnpm build
pnpm tauri:dev
pnpm test:e2e
pnpm rust:check
pnpm rust:fmt:check
pnpm rust:test
pnpm package:exe
```

按项目阶段实际有无对应测试脚本执行；尚未建立的脚本不作为该阶段门槛。`pnpm tauri:dev` 必须在 Windows 图形桌面实际打开应用并完成该阶段列出的主流程验证。`pnpm package:exe` 使用 `tauri build --no-bundle` 构建，不生成安装程序，并把 `src-tauri/target/release/juju-desktop.exe` 复制到 `artifacts/Juju.exe`。每个完成阶段都必须重新生成该 EXE。阶段报告记录命令、结果、手动验收结果、已知问题和未执行项目。可复用上一阶段的检查，但源代码变化后必须重跑受影响检查。

## 2. 阶段路线图

### 阶段 0：可启动的桌面工程骨架

**产品结果：** 一个可安装依赖、可开发运行、可构建的 Juju 桌面空壳；主窗口显示产品名称、版本和明确的“功能建设中”内容，退出路径可用。

**实施内容：**

- 建立 `desktop/` pnpm 工程、React/TypeScript/Vite 入口、Tauri 2 Rust crate 和 Windows capability 配置。
- 建立可运行的主窗口、基本错误呈现、日志入口和开发/构建脚本；锁定依赖版本。
- 建立测试、格式、静态检查配置，以及 `desktop/README.md` 的开发指引。
- 不生成自动更新或自动发布配置，不添加尚未使用的业务依赖；阶段完成时产出 `artifacts/Juju.exe`。

**验收：** 在 Windows 开发环境执行 `pnpm install --frozen-lockfile`、共同验收命令；主窗口可启动、关闭并再次启动；前端构建及 Rust 编译通过。

### 阶段 1：Design Tokens 与 Ju 组件体系

**产品结果：** 阶段 0 应用继续可运行，并提供可在桌面应用中交互的设计系统工作台。

**实施内容：**

- 集中建立颜色、字体、尺寸、间距、边框、焦点和状态 tokens；支持 Light、Dark、System。
- 建立 shadcn/ui 底层实现和 `Ju` 公共组件入口，落实 `new-ui.md` 的组件约束。
- 按核心交互优先实现 Button、Input、Select、Dialog、Tabs、Table、Toolbar、StatusBar、Toast、Empty/Loading 等组件与页面布局。
- 建立组件工作台，真实展示组件状态、主题和布局；增加组件测试与导入/样式规则检查。
- 此阶段不实现 Toto、JSON、MySQL 业务，不要求已有工具后端服务。

**验收：** 从主窗口可进入工作台；组件交互、键盘焦点和主题切换可实际操作；Vitest 覆盖核心 Ju 组件，Playwright 验证主题持久化、弹窗、标签页和导航；静态规则能验证业务层经 Ju 组件入口使用公共控件。

### 阶段 2：应用主体、设置与通用宿主能力

**产品结果：** 可日常运行的 Juju 应用主体：Launcher、设置中心、托盘和工具目录可用；尚未实现的工具以可识别的开发中状态呈现。

**实施内容：**

- 完成统一窗口布局、Launcher 工具目录、键盘导航、主快捷键和窗口管理。
- 实现设置界面及应用级设置持久化：主题、启动行为、快捷键、工具列表密度、数据根目录等适用设置；保存失败给出反馈并保留有效旧值。
- 实现托盘显示/隐藏 Launcher、打开设置、退出；关闭窗口只销毁窗口，主进程驻留。单实例激活复用已有 Launcher。
- 实现明文文件数据根目录、应用配置/窗口状态、原子写入和路径校验；遵循功能规格中目录切换和关停顺序。
- 实现 Rust 宿主的通用任务调度接口和生命周期：工具可登记、取消、恢复/时间变化后重新计算任务；调度器不持有 UI 状态。先用可控演示任务验证，不提前加入 Toto 业务规则。
- 实现工具窗口注册、稳定 label、创建/聚焦/销毁及窗口生命周期事件；跨窗口通过宿主命令/事件协调必要状态，不假设共享前端 Store。
- 基础能力包含快捷键、通知、文件/目录对话框、应用日志和系统恢复事件适配；只开放最小必要权限。
- 不实现自动发布、更新检查或自动升级；阶段交付只打包 EXE，不生成安装程序。

**验收：** 主窗口关闭后应用仍在托盘；托盘能恢复主窗口和设置；工具窗口可关闭销毁并再次创建；设置重启后保持；演示调度任务在窗口销毁后仍触发；退出后后台任务停止；跨窗口主题设置一致。

### 阶段 3：Toto 工具

**产品结果：** Toto 可独立打开/关闭窗口，数据持久化，应用留在托盘时提醒仍正常。

**3.1 Toto 数据与事项工作流**

- 实现 Toto 明文配置、CSV 读写、原子保存、数据初始化和现行格式兼容。
- 实现快速新增及时间解析、进行中事项列表、编辑、完成、取消、详情和刷新。
- 提供历史查询窗口与分页；暂时未接入调度时，提醒状态和计划信息仍可查看。

**验收：** 应用可启动进入 Toto；事项新增/编辑/完成/取消后重启仍一致；CSV 可由外部编辑后重新读取；历史筛选、分页、排序对照功能规格。

**3.2 Toto 后台提醒、盘点与设置**

- 将 Toto 提醒作为宿主长期后台模块启动，接入通用调度器；实现日历加载、重试、提醒持久化后通知、每日盘点去重、锁屏/解锁/电源恢复/系统时间变化处理。
- 实现 Toto 热键、提醒提前量、盘点时间/工作日和日历编辑设置。
- 实现提醒/盘点窗口、通知和日志；关闭 Toto 窗口不影响后台运行。

**验收：** 使用可注入时钟/调度测试验证到期、提前量、每日去重及恢复重算；手动验证托盘驻留期间提醒；提醒先持久化再呈现，重启不重复提醒；日历失败按规格重试。

### 阶段 4：JSON 工具

**产品结果：** JSON 工具可管理多个本地文档，支持编辑、保存、格式化和数据恢复，文档明文可由外部编辑。

**4.1 文档管理与可靠持久化**

- 建立文档、元数据和设置文件；支持新建、打开、列表筛选、重命名、删除到回收目录、排序、导入和启动恢复。
- 实现原子保存、自动保存、保存状态、版本戳、文件观察和外部修改冲突处理。
- 可先用 Ju 多行输入编辑器交付真实可用的文档管理版本；编辑器接口保持可替换。

**验收：** 文档生命周期操作重启后保持；外部修改干净文档会刷新；有未保存修改时提供规格规定的冲突选项；失败操作不丢失源文件。

**4.2 编辑器能力、对比和导出**

- 集成 Monaco 与版本化 Tauri 消息协议，支持 JSON 校验、格式化、折叠、光标状态、缩进设置和大文件提示。
- 实现文档对比、压缩复制、复制文本/文件、拖放导入和命令快捷键。
- 实现设置界面、剪贴板临时文件及过期清理。

**验收：** 实际启动 JSON 窗口；有效/无效 JSON、编辑器命令、文档切换保存、Diff、拖放/剪贴板与快捷键分别通过自动测试及桌面验收。

### 阶段 5：MySQL Schema 工具

**产品结果：** 用户可管理连接、测试数据库、创建结构快照、查看历史并对比结构；建议 SQL 只供查看/复制，不执行。

**5.1 连接管理与数据库浏览**

- 实现明文 `connections.json`、连接新增/编辑/删除/复制/搜索、真实连接测试和数据库/表/视图枚举。
- 密码不得写入日志；删除 profile 不删除已有快照。
- 提供无数据库环境时的清晰提示，单元测试使用可替换连接边界。

**验收：** 无配置时可打开工具并看到空状态；提供有效 MySQL 时可以测试连接和枚举对象；重启连接保留；明文密码存储行为符合用户决定且不进入日志。

**5.2 结构备份与快照浏览**

- 实现环境/版本/连接/数据库/对象快照目录树、原位新增/重命名/删除、备份选择流程和逐对象结果。
- 持久化 Catalog 与快照 JSON；采集结构元数据、DDL 和警告，不采集行数据；支持离线查看、详情和 JSON 导出。

**验收：** 使用测试 Schema/可控 fixture 验证表、视图快照、重复对象保护、部分失败、删除规则和离线读取；快照结构和文件路径符合功能规格。

**5.3 结构对比与迁移建议**

- 支持快照与实时对象选择、A/B 交换、差异分类、对象明细、元数据和原始 DDL 查看。
- 生成受支持范围内的方向性 SQL 草案和明确警告；草案不自动执行。

**验收：** 用版本化 Schema fixture 覆盖新增/删除/修改及不支持结构；对比结果稳定；UI 标示 SQL 是审阅草案且没有执行数据库语句的路径。

### 阶段 6：全产品集成与回归

**产品结果：** 应用主体和三个工具作为同一桌面产品协同运行。

**实施内容：**

- 对照功能规格逐项完成功能/数据格式/快捷键/启动/关停回归。
- 验证托盘生命周期、单实例、窗口销毁与重建、主题、文件根目录、安全退出、后台 Toto 调度和日志。
- 验证新旧格式兼容及明文数据可读、可手工编辑；修复工具间目录、快捷键、窗口和主题冲突。
- 完善文档、自动化测试、架构测试及桌面人工验收清单。

**验收：** 每个工具独立流程和跨工具主流程均通过；共同验收门槛通过；没有未说明的数据丢失或阻塞性缺陷；形成完整阶段报告。

## 3. 阶段门禁与范围变更

- 每阶段在计划中有对应的产品结果、可演示路径和验收记录。不能以“代码已写完”作为完成依据。
- 自动化测试优先覆盖领域逻辑、文件格式、原子操作、调度、冲突处理、Tauri 命令和关键窗口生命周期；人工验收补足原生托盘、通知和视觉检查。
- 涉及格式迁移、数据根目录复制/切换、明文凭据可见性、调度恢复策略或用户可见行为变化时，先作为产品决策确认，再实施。
- 若阶段发现后续依赖问题，可调整顺序，但不得降低“每阶段有可运行、可验证产品”的门槛；调整需记录原因与新验收条件。
- MSI/NSIS 安装文件、自动发布、更新检查和自动升级属于明确排除范围；单文件 `Juju.exe` 是每阶段的强制交付项。
